# Объединение арен utils и adaptive

В utils остаётся одна реализация аллокатора — `utils.Arena`.
Пакет `utils/arena` содержит алиасы типов и конструкторы для режима NonMoving.
Adaptive использует этот пакет напрямую; внутренний аллокатор и его копии тестов
перенесены в utils.

Исходные версии для сопоставления: utils `e3ac1ed35203` и adaptive
`e91e7d889988`. Исторические реализации нужны только для воспроизводимого
бенчмарка: скрипт извлекает их во временный каталог через git show.

## Выбор режима и быстрые операции

| Свойство | Исходная utils | Исходная adaptive | Общая utils по умолчанию | Общая NonMoving |
|---|---|---|---|---|
| Малые классы | 9 | 18 всего | Те же 9 | 18 всего |
| Payload 8192 байта | Блок 8208, без класса | Класс 8256 | Блок 8208, без класса | Класс 8256 |
| Полностью пустой регион | Только madvise, курсор не возвращается | Повторное использование | Повторное использование и madvise | Повторное использование, Trim отдельно |
| Разреженный живой регион | Подсказка эвакуации | Списки остаются доступны | Подсказка эвакуации | Списки остаются доступны |
| Поиск свободного класса | Обратный проход по регионам | Битовая карта | Прежний проход до 256 регионов, затем карта | Прямой доступ к последнему региону, затем карта |
| Незанятый TLAB при OOM/Close | Не возвращается | Возвращается | Возвращается | Возвращается |
| Stats / Trim / zeroed / capacity | Нет | Есть | Есть | Есть |

Сохранены inlineable `utils.GetSizeClass` с исходными девятью классами и
непроверяемый `GetPtr`. Расширенные классы включаются только в NonMoving.
Проверяемые операции доступны явно: `CheckedPtr` и `PayloadCapacity`.
Подсчёт свободных блоков выполняется в Stats, а не на каждом Alloc/Free.
Stats обходит цепочки под блокировками; это диагностика вне пути запроса.

Для default после инициализации более 256 регионов включается битовая карта.
Её начальная сборка синхронизирована с Free: публикация полного индекса завершается
до перехода PopBatch на него. Новые тесты проверяют уже освобождённые блоки,
одновременные выделения во время переключения и повторное открытие файла.
Сам watermark вычисляется целочисленным сравнением; в NonMoving он равен нулю.

Размер записи региона вырос со 128 до 256 байт. На amd64 для mapping 1 GiB
метаданные составляют 132352 вместо 65600 байт: дополнительно около 65 KiB,
или 0,0062% mapping. На объект это не добавляет Go-указателей или обёрток.
Таблица фиксированного размера также сохраняет чтение старого формата adaptive.

Резервирование новых порций и повторное использование регионов синхронизированы
общим медленным мьютексом. Повторное выделение малого блока и обычный Free
его не берут, пока регион не опустеет. Новая anonymous mmap не обходит всю
таблицу метаданных: нулевые страницы ОС остаются ленивыми.

## Совместимость

**Формат mmap-файлов исходной utils меняется.** Старый заголовок и таблица
регионов отвергаются; такую арену следует пересоздать из данных приложения.
Исходный конструктор Go сохраняется. Это изменение формата, а не автоматическая
миграция содержимого.

NonMoving открывает файлы прежнего adaptive после штатного Close, сохраняя
смещения объектов. Обратный переход к старому аллокатору не поддерживается.
Режим и размер mapping должны совпадать при повторном открытии.

В NonMoving нет перемещения живых объектов. Default также ничего не перемещает
самостоятельно: NeedsEvacuation служит подсказкой внешнему владельцу.
Free требует отсутствия читателей; Close — завершения всех пользователей.
Формат mmap не является протоколом восстановления графа приложения после сбоя.

## Проверки

Общие тесты покрывают прежние контракты utils, оба режима освобождения, точные
блоки и классы, длительный оборот сверх ёмкости mapping, учёт claims, активные и
потерянные из sync.Pool TLAB, конкурентные Trim/Stats/Alloc/Free, смещения выше
4 GiB, метаданные в нескольких регионах и несовместимые файлы.

Проверенная рабочая версия прошла functional, race, checkptr, vet и ownership
fuzzing на native Linux amd64 и arm64. Выполнена cross-сборка для riscv64.
Новые тесты индексирования проверяют переключение в default, сохранение прежних
свободных блоков, конкурентный доступ и повторное открытие большой арены.

## Измерения

Кандидат: `f3373dcd0ab7`. Последующее форматирование исходников не меняет алгоритм.
Прогон: [GitHub Actions 42071950063](https://github.com/banditmoscow1337/adaptive/actions/runs/42071950063).
Общая реализация проверена отдельно на [native amd64 и arm64](https://github.com/banditmoscow1337/utils/actions/runs/42071545048).
Интеграция adaptive закрепляет тот же исходный модуль.

Go 1.27.2, Linux amd64, Intel Xeon Platinum 8370C, восемь повторов,
`-benchtime=150ms -cpu=1,4`. P означает GOMAXPROCS. Все четыре варианта
выполнялись на одном runner через один интерфейс. Здесь приведены медианы,
полные образцы сохранены в [arena-comparison-amd64.txt](benchmarks/arena-comparison-amd64.txt).
Таблицы используют ns/op; меньше — быстрее. Это микробенчмарки аллокатора,
а не результат производительности GGDB, ART или всего AdaptiveList.

### Прежняя utils и общий default

| Операция | Исходная utils | Общая default | Изменение времени |
|---|---:|---:|---:|
| Alloc/Free 16 B, P=1 | 73.97 | 76.20 | 3.0% |
| Alloc/Free 64 B, P=1 | 73.77 | 76.25 | 3.4% |
| Alloc/Free 4096 B, P=1 | 75.88 | 79.50 | 4.8% |
| Alloc/Free 4096 B, P=4 | 75.00 | 79.77 | 6.4% |
| Parallel reuse, P=4 | 99.03 | 98.94 | -0.1% |
| GetPtr + read, P=1 | 1.954 | 1.955 | 0.1% |
| Empty PopBatch, 16 regions | 26.09 | 27.21 | 4.3% |
| Empty PopBatch, 512 regions | 808.10 | 11.54 | -98.6% |
| Empty PopBatch, 2048 regions | 3219.5 | 29.01 | -99.1% |
| AllocBatch + claims + Free, P=1 | 5003.0 | 827.80 | -83.5% |
| AllocDense/Free parallel, P=4 | 1120.0 | 133.55 | -88.1% |

На коротких Alloc/Free default получил **около 3–6% накладных расходов**:
в этих образцах примерно 2–5 ns на пару операций. Это сохраняющаяся цена выбора
политики и обслуживания общей реализации; утверждения о полном отсутствии
регрессий здесь нет. GetPtr сохранил время около 1,95 ns в проверке с чтением.
Параллельное повторное использование практически совпало с исходным.

Промах по свободному классу после роста ускорился примерно в 70 раз для
512 регионов и в 111 раз для 2048. Этот тест исключает подготовку mapping:
разовая сборка индекса при переходе через порог не входит в ns/op промаха.
На небольшой арене промах остаётся обычным проходом.

Batch включает AllocBatch(1024,16), возврат 15 claims и Free. Его ускорение
примерно в шесть раз относится к полному циклу повторного использования региона,
включая поведение madvise и page faults. Это не измерение одного первичного bump.
AllocDense теперь также умеет повторно брать класс из free list; поэтому его
параллельный цикл сравнивает результирующее поведение API с этой возможностью.

Cold Burst создаёт mapping, выделяет и освобождает 256 объектов, записывая одно
слово в каждый payload, затем закрывает арену. Для P=1 медианы default:
8 KiB — 313.36 → 319.13 μs;
16 KiB — 324.84 → 329.93 μs;
64 KiB — 349.49 → 354.86 μs
**на весь burst**, не на один объект. В вариантах P=1/4 изменения составили
примерно +1–4%. Полная запись payload и пропускная способность памяти здесь
не измеряются.

### Прежняя adaptive и общая NonMoving

| Операция | Исходная adaptive | Общая NonMoving | Изменение времени |
|---|---:|---:|---:|
| Alloc/Free 16 B, P=1 | 81.06 | 76.73 | -5.3% |
| Alloc/Free 64 B, P=1 | 80.06 | 77.17 | -3.6% |
| Alloc/Free 4096 B, P=1 | 83.23 | 80.09 | -3.8% |
| Parallel reuse, P=4 | 94.55 | 97.58 | 3.2% |
| Empty PopBatch, 16 regions | 4.284 | 5.791 | 35.2% |
| Empty PopBatch, 512 regions | 17.48 | 11.54 | -34.0% |
| Empty PopBatch, 2048 regions | 59.40 | 28.96 | -51.2% |
| AllocBatch + claims + Free, P=1 | 333.45 | 161.15 | -51.7% |

В повторном использовании малых классов общая NonMoving оказалась быстрее
прежней adaptive примерно на 4–5% в этом прогоне. Параллельный reuse с P=4
подорожал примерно на 3%; маленький чистый промах — примерно на 1,5 ns.
Большие промахи и цикл Batch ускорились. Эти результаты не сводятся к одному
универсальному коэффициенту ускорения. В hot reuse все варианты дали 0 allocs/op.

Отдельный унаследованный BitmapChurn в raw-файле относится к исторической
experimental. Межверсионные сравнения используют именованные backends:
original = utils e3ac1ed; experimental = adaptive e91e7d8;
shared = общий default; nonmoving = общая NonMoving.

### Воспроизведение

Из полного checkout utils, рядом с checkout adaptive:

```sh
python3 scripts/arena-compare/run.py --adaptive-repo ../adaptive \
  --output /tmp/arena-comparison.txt --count 8 --benchtime 150ms --cpu 1,4
```

Скрипт извлекает старые arena.go/метаданные через git show во временный модуль,
запускает проверку реальных файлов обеих исторических реализаций и затем
бенчмарки. Старая utils должна быть отвергнута новым reader; файл старой adaptive
должен открыть NonMoving, сохранить payload и вернуть все claims после Free/Trim.
Исторические реализации не остаются в активных пакетах или зависимостях.

Повторные прогоны на другом CPU, ядре Linux и с другой частотой дают другие
абсолютные числа. При выборе режима нужно учитывать собственную долю выделений,
требование эвакуации и профиль размеров, а не переносить коэффициент пустого
PopBatch на полную работу приложения.
